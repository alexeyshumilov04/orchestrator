# 17. Вкладка «Граф моделирования» в веб-интерфейсе

Задача: показать в интерфейсе последовательность получения модели, решения агентов,
точки ветвления ансамбля и вызванные проверки Метакритика — **только из данных**
отчёта/API, без зашитых названий этапов, шагов и проверок.

Состав среза:
`api.py` — эндпоинт `GET /api/runs/{run_id}/graph` + сборщик узлов/рёбер;
`frontend/index.html|app.js|styles.css` — вкладка «Граф моделирования»;
`tests/test_graph_tab.py` — 35 проверок (включая data-driven тест frontend).

---

## 1. Откуда берутся данные

Граф собирается из **артефактов прогона на диске**, а не из состояния веб-слоя:
оно хранится сжатым (`_PERSIST_RESULT_KEYS`) и после перезапуска сервиса не содержит
ни шагов, ни проверок.

| Артефакт | Что даёт графу |
|---|---|
| `report_execute.json` / `report.json` | этапы агентов (`agents.stages`), вердикт Метакритика и QA/QC, ансамбль (`project.ensemble`: ветви, метрика, `best`, `scored`), модель (сетка, `stoiip`), манифест артефактов (`model_artifacts`), сводка шагов |
| `steps.json` | последовательность шагов: этап, функция, объект, статус, сообщение, время |
| `agents/gates/<GATE>.json` | проверки гейта: `id`, `severity`, вердикт, `message`, `remediation`, `evidence`, `kq`/`kc`/`physical`, попытки |
| `agents/handoffs/<NN>_<GATE>.json` | решения агентов: `from_agent/to_agent`, вердикт, `degraded`, `uncertainties`, `unresolved_findings`, `evidence_hash`, `artifact_revisions`, `lineage` |

Выбор отчёта — параметр `source`:

* `auto` (по умолчанию) — по признаку прогона (запись execute/dry-run), а если он
  неизвестен — предпочитается отчёт, в котором есть данные выполнения (ансамбль/модель);
  так dry-run, перезаписавший `report.json` после реального прогона, не «затирает»
  граф с ветвями;
* `execute` — `report_execute.json` (реальный прогон);
* `dry` — `report.json` (dry-run).

Ответ всегда сообщает, какие отчёты есть в каталоге (`sources.available`) —
интерфейс показывает переключатель, если их больше одного.

## 2. Эндпоинт `GET /api/runs/{run_id}/graph?source=auto|execute|dry`

Структура ответа (машиночитаемая, frontend только отображает):

```jsonc
{
  "run_id": "…", "field": "…", "run_status": "done", "available": true,
  "sources": { "report": "…report_execute.json", "report_kind": "execute",
               "available": [{"kind":"execute","file":"report_execute.json",…},
                             {"kind":"dry","file":"report.json",…}],
               "steps": "…steps.json", "gates_dir": "…", "handoffs_dir": "…" },
  "summary": { "steps": {…}, "stages_total": 12, "gates_total": 8,
               "gates_with_failures": {…}, "critic_verdict": "…",
               "qaqc": {…}, "branches_total": 5, "best_branch": "S002",
               "metric_name": "STOIIP",
               "grid": {"nx":250,"ny":311,"nz":22,…}, "stoiip": 18024.6, "tnav_ok": true },
  "nodes": [ { "id": "stage:0", "type": "stage|step|agent|gate|check|critic|ensemble|branch|artifact",
               "label": "…", "subtitle": "…", "status": "…",
               "tone": "ok|warn|bad|info|neutral", "col": 0, "row": 0, "attrs": {…} } ],
  "edges": [ { "id": "…", "from": "stage:0", "to": "step:1",
               "type": "contains|next|agent|decides|gate|checks|branch|lineage",
               "label": "…" } ],
  "legend": { "tones": [...], "types": [...] },
  "warnings": [ "…" ]
}
```

Ошибки — честные, без пустого графа: `404` — прогон неизвестен; `409` — у прогона нет
каталога артефактов или отчёта ещё нет (прогон идёт), с причиной; `400` — неизвестный
`source` (перечисляются допустимые).

Верстка позиций (`col`/`row`) считается на сервере: этапы — по колонкам, шаги внутри
колонки, решения агента и гейт — рядом, проверки гейта — под гейтом, ансамбль и ветви —
в последних колонках. Цвет (`tone`) тоже решает сервер по данным, поэтому в frontend
нет ни названий, ни порогов.

## 4. Что видно на вкладке

* **Сводка** — чипы: поле, статус прогона, этапов/шагов (done/error), гейтов,
  вердикт Метакритика, ветвей и лучшая, сетка (из отчёта).
* **Граф (SVG)** — колонки по этапам: этап → его шаги (рёбра «содержит»/«далее»),
  решение агента (кто/вердикт/свидетельства), гейт с проверками, отдельные колонки
  ансамбля (ветви, лучшая подсвечена) и манифеста артефактов; связи lineage —
  пунктиром, ветвление — акцентом. Цвет узла и строк проверок — по `tone` из данных.
* **Клик по узлу** — панель деталей: атрибуты шага/гейта, таблица проверок
  (id · уровень · вердикт · что проверено · remediation), свидетельство (JSON),
  счётчики по уровням, QA/QC, параметры и метрики ветви, lineage, ревизии артефактов
  (путь + sha256), незакрытые находки, выборка правил Метакритика.
* **Переключатель отчёта** — появляется, когда в каталоге есть и реальный прогон, и
  dry-run (`sources.available`), значения и подписи приходят из API.
* **Прогон без ансамбля** — граф строится, узлов ветвей нет, в `warnings` фиксируется
  «ансамбль в данных прогона не объявлен»; узлы шагов/гейтов/проверок на месте.

## 5. Согласованность артефактов (важно для доверия к графу)

Каталог прогона `runs/run_<поле>/` **переиспользуется**: `report_execute.json` может
остаться от предыдущего прогона, а `steps.json`, `agents/gates/*.json`,
`agents/handoffs/*.json` — уже от следующего (измерено на живом каталоге: отчёт
14:33:10, шаги/гейты 15:31–15:32, разница ~1 час). Снапшот
`runs/artifacts/execute_<ts>/` пока содержит только `report_execute.json`, поэтому
«взять всё из снапшота» сейчас невозможно — это находка web-run-fix; структурный
вариант (разделять каталоги execute/dry-run) решает Lead.

Пока это не решено, граф **не маскирует** смешение:

* `sources.artifacts` — для каждого источника (report / steps / gates / handoffs):
  путь, `mtime`, `ts`;
* `summary.artifacts_consistent` — `true` (все в пределах допуска
  `_GRAPH_ARTIFACT_MTIME_TOL_SEC = 120` с от отчёта), `false` (артефакты от разных
  прогонов) или `null` (сравнивать нечего — неизвестное, а не «всё хорошо»);
* при `false` в `warnings` попадает строка с временами и величиной расхождения, а на
  вкладке появляется чип «⚠ артефакты от разных прогонов»; данные шагов/гейтов при
  этом остаются как есть — пользователь видит, что вывод по ним может не
  соответствовать отчёту (правило 6: неизвестное не выдаём за факт).

Проверяется тестом: согласованный прогон → `true` без предупреждения; искусственно
состаренный `steps.json` → `false` + предупреждение; только отчёт → `null`.

## 6. Тесты

`tests/test_graph_tab.py` (39): маршрут зарегистрирован, прежние маршруты не потеряны;
сборка графа на фикстуре с нейтральными именами (типы узлов/рёбер, связность, `tone`,
caps выдачи проверок, решения агентов со свидетельствами и lineage, Метакритик, ветви
и лучшая); прогон **без ансамбля** и **без отчёта** (честный `available=false`);
обработчик эндпоинта `200/404/409/400` (без сети); выбор источника `auto|execute|dry`;
согласованность артефактов (`true`/`false`/`null`); frontend — запрашивает эндпоинт,
рисует по `label`/`subtitle`/`attrs`, и **data-driven чёрный список**: названия этапов,
гейтов и ветвей берутся из реального отчёта, и ни одно не встречается в `app.js`/
`index.html`; отдельно — реальный прогон (5 ветвей, `best=S002`, сетка 22 слоя).
Плюс регламентная батарея (включая `test_verify_*.py`), `preflight`, dry-run двух полей.

## 7. Что осталось

* **Ограничение выдачи проверок**: узлы проверок — до `_GRAPH_MAX_CHECKS_PER_GATE`
  (40) на гейт, правила Метакритика — выборкой до 40 (в отчёте 6117 — все «unknown»
  при отсутствии формализованных правил). Полные перечни видны в отчёте/QA/QC-пакете,
  в графе — сводка и счётчики.
* **Ручная визуальная проверка в браузере** не выполнялась (нет браузерного клиента в
  сессии): проверено сырыми HTTP-запросами (SPA, статика, эндпоинт) и структурными
  тестами. Разметку вкладки стоит посмотреть глазами на том же URL.
* **Реальный прогон `--execute`** для проверки вкладки не запускался (приёмка — за Lead);
  граф проверен на уже существующем артефакте принятого прогона.
* **Согласованность артефактов** — сейчас только диагностируется (см. §5); структурный
  фикс (разделение каталогов execute/dry-run либо полный снапшот со steps/gates) —
  решение Lead; после него предупреждение должно исчезнуть на нормальных прогонах.
