# Универсальность: проверка на втором объекте (ТЕСТ2) и правила привязок

## Зачем

Требование заказчика: «проверь на втором тестовом объекте, чтобы убедиться, что ничего не
захардкожено» и «все правила должны быть в онтологии, а не в проектном графе».
ТЕСТ2 — намеренно другой формат данных (Petrel Well Tops, колоночный Well_Header,
`dev/*.dev`, мнемоники в cp1251, поверхность `.irap`).

## Что выяснилось про шаблоны tNavigator (важное)

1. В шаблонах **49 имя-подобных аргументов**, часть уже использует плейсхолдеры
   (`__MESH__`, `__BLOCKED_WELLS__`, `__RESULT_PROPERTY__`, `__MAP__`).
2. У **работающего** поля (Герасимовское) **39 объектных аргументов остаются непривязанными**,
   и в них «протекают» значения демо-проекта (`Boundary`, `C1tl_Z`, `Default Set`,
   `Intersection1`, `LG`, `Vrez`). Прогон при этом проходит: часть таких шагов уходит
   в пропуск по другим политикам, а часть аргументов имеет законные значения по умолчанию.
3. **Отсюда вывод:** подход «шаг без привязки → пропускать» **тупиковый** — те же значения
   нужны рабочему полю (например, `horizon_interpolate_by_marker_idw` строит кровлю).
   Трижды проверено: включение такого правила резало законные шаги (7–10 ложных пропусков)
   и ломало приёмку (`scored: 0`), после чего откатывалось.
4. Правильное решение — **вывод привязок из данных поля**: заполнять аргументы значениями
   распознанных ролей и **заменять** протёкшие значения; пропускать только шаги, объявленные
   необязательными в данных. Это описано в `ontology/object_binding_rules.yaml`.

   `objects_bindings: passed`.
3. Обязательное условие (правило 3): приёмка Герасимовского сохраняется —

## Находки о данных Герасимовского (измерено, влияет на петрофизику)

* `PHIE` — **целые проценты**, всего 9 значений, из них 65 % равны 3 % → куб пористости
  ступенчатый; перевод процентов в доли **применяется** (модель 0.049 против LAS 3.0).
* `KINT` — **не проницаемость**: 78 % замеров равны 1.0, бланков 39 % → источник `PERM`
  помечен `failed`; правильный путь — керновая k-φ (в проекте керна нет — проверено
  обходом данных), иначе литература со статусом кандидата, иначе `unknown`.
