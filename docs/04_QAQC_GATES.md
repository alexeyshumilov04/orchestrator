# 04. QA/QC как гейты: проверки, покрытие, семантика

Документ описывает QA/QC-слой `orchestrator_v8`: откуда берутся проверки, как они
привязываются к гейтам, что означают исходы и какие артефакты появляются.

## 2. Семантика исходов (правило 6 «неизвестное ≠ ложь»)

| Исход | Условие | Влияние на вердикт |
|---|---|---|
| `passed` | данные есть, критерий выполнен | не штрафует |
| `failed` | данные есть, критерий нарушен | штрафует (`critical` → `failed` гейта) |
| `not_applicable` | входных ключей нет ИЛИ вычисление невозможно | НЕ штрафует (нет суждения) |
| `unknown` | правило не формализовано / критерий качественный | НЕ штрафует, виден в отчёте |

Сводные метрики: `applicable = passed + failed`; `kq` — среднее по проверкам с
`fitness_function='да'` (37 исторических + новые), `kc` — по остальным применимым;
`fitness = alpha*kq + beta*kc` (веса — данные `checks.fitness_alpha/beta`).
**`physical` — три состояния**: `true` (применимые проверки прошли), `false` (есть провалы),
`null` — применимых проверок не было, то есть «не проверялось». Отдельный флаг
`physical_known` показывает, что значение известно.

Пороги качества `min_kq/min_kc` механизм поддерживает, но **в данных не заданы
осознанно**: на текущем уровне оцифровки (block 13 → 0 исполняемых, большая часть
ключей кубов ещё `planned`) включение порога деградировало бы гейты из-за неполноты
QA/QC, а не из-за качества модели. Предохранитель — `checks.min_applicable_checks: 5`:
пока применимых проверок меньше, пороги не действуют.

## 3. Покрытие чеклиста (6065 пунктов)

Источник — `QAQC/QA_QC_чеклист.xlsx` (лист «Чек-лист», 6065 строк, 23 колонки).
Артефакты покрытия — два, с разными ролями:

| Артефакт | Роль |
|---|---|
| `domain/qaqc/qaqc_coverage.json` | статический аудит ПАКЕТА (что формализовано в данных/коде) |
| `runs/<id>/qaqc_coverage.json` | артефакт ПРОГОНА (по живому каталогу и живым значениям) |

Текущее состояние (`domain/qaqc/qaqc_coverage.json`):

```
6065 = implemented 288 + not_applicable 417 + unknown 5360
причины: R0 формализовано 288 · R1 слаг-ключ 417 ·
         R3 качественный критерий 7 · R2 не формализовано 4606 ·
         R4 вне 13 блоков ГПН 747 (195 пунктов вынесены построчно)
```

`implemented` означает «формализовано и вычислимо», а не «пройдено»: ни один пункт
чеклиста не помечается «пройдено» без данных.

## 4. Применимость: почему сейчас `applicable = 0` в dry-run

`applicable = 0` — честный результат, а не дефект: значения модели снимаются с
**открытого проекта** (пробники), а в dry-run проекта нет. Слой значений сейчас умеет
отдать `H_TOP, H_BOT, THICKNESS, OBSERVED, MODEL, H_WELL, GRID, H_GRID` и, при
`--execute`, средние кубов (`poro_mean/perm_mean`). Этого хватает части проверок
блока 02–04.

Чтобы 55 новых проверок стали применимыми, пробники должны отдавать ключи контракта
`ontology/qa_checks/model_keys.csv` (80 имён: массивы/статистики `PORO/PERM/SW`,
вариограмма `NUGGET/PARTIAL_SILL/SILL/RANGE_*`, `NTG_*`, `V_*`, `PV_*`, `N_*`,
`WOC_DIP_DEG`, `PERM_DYKSTRA_PARSONS`, `PERM_H/V`, `MEAN_WELL_SPACING_M`).
Ключи керна/SCAL (`ARCHIE_*`, `KOZENY_*`, `LOG_PERM_*`, `K_THEORY`) останутся
`not_applicable` — в проекте нет источника, и выдумывать значения запрещено.

## 5. Артефакты и прослеживаемость

```
runs/run_<поле>/
├── qaqc.json              сводка: total/passed/failed/not_applicable/unknown/applicable,
│                          by_block, by_source, kq/kc/fitness, physical(+physical_known),
│                          failed_checks (id, name, block, message, values)
├── qaqc_coverage.json     покрытие чеклиста по блокам + items_outside_blocks построчно
├── agents/gates/<gate>.json   вердикт гейта: counts, findings, thresholds{applied,skipped,
│                          applicable, required_applicable}, physical, attempts, mode
├── agents/handoffs/NN_<gate>.json  меморандум: ревизии, lineage, qa, assumptions, evidence_hash
└── agents/kb/<agent>.jsonl    опыт агента: вердикт, метрики, параметры, evidence_hash
```

## 6. Что проверено, а что осталось открытым

**Проверено:**
* `qaqc` присутствует в `report.json` верхнего уровня, `physical = null` при нуле применимых
  (находка независимого верификатора закрыта);
* `min_kq/min_kc` не применяются без данных и без достаточного числа применимых проверок
  (`checks.min_applicable_checks: 5`), зафиксировано тестами `tests/test_contracts.py` (82);
* пороги 62 новых проверок сверены с чеклистом (46 сверок — 0 расхождений);
* историческая база 652 проверок не изменена (SHA-256 сверяется генератором);
* 7 качественных критериев вынесены в `DESCRIBED_ONLY` → `unknown`, а не «пройдено».

**Открыто:**
* 80 ключей `model_keys.csv` объявлены (`planned`), пробники их пока не отдают → 55 проверок
  в `not_applicable` (follow-up E3, задача `task-8`);
* 418 исторических проверок со слаг-ключами принципиально невычислимы без ручного маппинга;
* блок 13 (петрофизика, 873 пункта) остаётся почти не формализованным — 10 проверок
  невычислимы (нужны керн/РИГИС-зависимости);
* блоки 11 (неопределённости) и 12 (ГДМ) вне объёма этой итерации (`out_of_scope` в данных).
