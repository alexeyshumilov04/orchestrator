# Проверка: общие правила и методы — в онтологии, а не в проектном графе (все агенты)

## Требование заказчика (раунд 87)

«Проверь, что всё внесено в онтологию **в общем виде**, а не в проектный граф. Это касается
**всех агентов и всех методов**».

## Метод проверки (воспроизводимый)

1. Собрать план **из онтологии** и посмотреть, какие правила/методы в нём есть:
   `python main.py graph --field <поле> --pipeline-from-ontology`
2. Инвентаризовать общие (не полевые) сущности в проектном графе.
3. Для каждой такой сущности указать, где она должна жить (файл онтологии) и есть ли она там.

## Факт проверки (раунд 86–87)

```
$ python main.py graph --field Герасимовское --pipeline-from-ontology
  → источник состава: ontology; этапов: 12; шагов: 51; уникальных функций: 29
ключи петрофизики в выведенном графе: []
perm_from_poro есть: False
```

**Итог: общие правила в план из онтологии НЕ попадали** — они лежали в
`ontology_project/gerasimovskoe.yaml` (подгонка под кейс). Исправление начато:
создан `ontology/petrophysics_rules.yaml` (правила петрофизики в общем виде).

## Критерий приёмки переноса (для ВСЕХ агентов)

Проверка выполняется на поле **без ручного** `ontology_project/<поле>.yaml`:

```
python main.py graph --field <поле> --pipeline-from-ontology
  в выведенном плане/решениях ОБЯЗАНЫ присутствовать:
   • структурный агент: порог вреза и состав метода вреза;
   • геостатистика: тип вариограммы и её параметры по умолчанию + правило выбора метода;
   • петрофизика: политика бланков, проверка единиц, источник k-φ (керн→литература→unknown),
     ограничение «единая k-φ недопустима»;
   • фации: метод и его параметры (уже есть);
   • насыщение/PVT/SCAL: корреляции и их провенанс;
   • волюметрия: правила расчёта и метрика ансамбля;
   • карты: перечень обязательных карт и уровни их проверок;
   • QA/QC: пороги приёмки с провенансом (литература/чеклист/заказчик).
```

Пока пункт не выполняется — соответствующие правила в проектном графе считаются
**временными** и не дают прототипу универсальности (критерий «г»).
