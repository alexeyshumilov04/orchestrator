# `ontology/qa_checks/` — оцифровка целевых проверок чеклиста ГПН (блоки 05…13)

Данные (не код). Читаются генератором `domain/qaqc/build_from_ontology.py`, который
дополняет пакет `domain/qaqc/` (652 существующие проверки **не меняются**) и собирает
`domain/qaqc/qaqc_coverage.json` по всем 6065 пунктам `QAQC/QA_QC_чеклист.xlsx`.

## 0. Два артефакта покрытия — разные роли (решение Lead, зафиксировано)

| Артефакт | Кто пишет | Что это |
|---|---|---|
| `domain/qaqc/qaqc_coverage.json` | генератор пакета (мой) | **статический** аудит ПАКЕТА: 6065 пунктов, статус «формализовано/неприменимо/неизвестно», provenance сборки, статус блока из чисел, `meta.items_outside_blocks` построчно |
| `runs/<id>/qaqc_coverage.json` | `agents/checks/report.py` (foundation) | артефакт ПРОГОНА: по живому каталогу, гейтам и значениям этапа |

Оба остаются; дублированием не считаются. `implemented` в любом из них означает
«формализовано», а не «проверка пройдена»: ранг применимости «здесь и сейчас» —
отдельно (`runtime` в моём артефакте, `states` в прогонном).

## 2. Формат `bNN.csv` — ровно как `domain/qaqc/checks_table.csv`

Разделитель `;`, UTF-8, шапка:
`ID;Блок;Название;Способ выполнения;Порог;Входные ключи;Значимость;Формула;Критерий;Используется критерием критика`

| Колонка | Семантика |
|---|---|
| `ID` | `QC_<ГРУППА>_NNN` — ID из чеклиста (уникален, с ID пакета не пересекается) |
| `Блок` | ПОЛНОЕ имя блока чеклиста; `by_block` = первые 2 символа |
| `Название` | «Проверка» из чеклиста — дословно |
| `Способ выполнения` | **имя примитива схемы** (`domain/qaqc/engine.PRIMITIVES`): `direct`, `diff`, `abs_diff`, `ratio`, `coverage`, `r2`, `pearson`, `spearman`, `rmse`, `mape`, `fraction_in_range`, `fraction_outside_range`, `null_fraction`, `zscore_max`, `mad_outlier_fraction`. Значение `unknown` = критерий **не формализован** в вычислимую метрику (проверка в `CHECKS` не попадает) |
| `Порог` | машинный порог; клаузы через `;` — по одной на ключ из `Входные ключи` в том же порядке |
| `Входные ключи` | ключи `DataContext` через `, ` (только имена из `model_keys.csv`) |
| `Значимость` | «Вес [0…1]» из чеклиста — дословно |
| `Формула` | «Метод / формула» из чеклиста — дословно; отсюда же берутся `lo`/`hi` для `fraction_*_range` |
| `Критерий` | «Критерий прохождения» из чеклиста — дословно |
| `Используется критерием критика` | `да` → проверка идёт в `kq` (качество результата), пусто → в `kc` |

### 2.1 Единицы порога (жёсткое правило разбора)

* метрика-доля (0…1): `r2`, `ratio`, `coverage`, `pearson`, `spearman`,
  `fraction_in_range`, `fraction_outside_range`, `null_fraction`, `mad_outlier_fraction`;
  знак `%` в `Порог` означает деление на 100 (`<= 5%` → `0.05`);
* метрика в процентах: `mape` (возвращает `|(a−b)/a|·100`). Порог для `mape`
  задаётся **числом без знака `%`** (`<= 30` = 30 % отн.) — генератор это проверяет;
* абсолютные метрики (`abs_diff`, `diff`, значения параметров в м/мД/д.ед./градусах) —
  порог в единицах метрики; для долей-абсолютных допусков знак `%` уместен (`ΔNTG ≤ 5% (абс.)` → `<= 5%`);
* `direct` — сравнение значения ключа с порогом «как есть»: единицы ключа и порога совпадают;
* `fraction_outside_range` — диапазон берётся из `Формула`; `Порог == 0` означает
  «все значения в диапазоне» (критерий чеклиста «Все ячейки в диапазоне»).

### 2.2 Значение `unknown`

7 проверок имеют качественный критерий, который нельзя свести к числу
(«Связность соответствует геологической концепции», «Нет угловатостей, изолинии гладкие»,
«J-функция универсальна для данного типа пород» и т. п.): `QC_LITH_005`, `QC_LITH_006`,
`QC_LITH_008`, `QC_LITH_010`, `QC_PERM_006`, `QC_SAT_007`, `QC_SAT_008`.
По правилу 6 это `unknown` (не `false` и не «прошло»): строка остаётся в данных с
`Способ выполнения = unknown`, пустыми `Порог`/`Входные ключи`, в `CHECKS` не попадает,
в покрытии получает статус `unknown` с причиной. Порог «на глаз» не выдумывается.

### 2.3 Порог, которого нет числом в «Критерий прохождения»

У 7 проверок критерий чеклиста сформулирован без числа, поэтому машинный порог
выведен строго из ДАННЫХ того же пункта (метода) или является точной формализацией
качественного требования. Ничего не «подобрано на глаз»:

| ID | Критерий чеклиста | Порог | Откуда число |
|---|---|---|---|
| `QC_GS_003` | «a ≥ среднее расстояние между скважинами» | `ratio(RANGE_M, MEAN_WELL_SPACING_M) >= 1` | 1 — нормировка тождества «≥ другого значения» |
| `QC_GS_006` | «Стабилизация достигнута» | `SIGMA_OVER_MEAN_RATIO <= 0.05` | 0.05 — из «Метод / формула» того же пункта: `σ(μ_N) / μ_N ≤ 0.05` |
| `QC_PERM_003` | «Аномалий нет» | `PERM_ANOMALY_FRACTION == 0` | 0 — «аномалий нет» ⇔ доля аномалий 0 |
| `QC_RES_008` | «Расхождений нет» | `abs_diff(PVT_MODEL, PVT_APPROVED) == 0` | 0 — «расхождений нет» ⇔ |Δ| = 0 |
| `QC_PHYS_001` | «Все ячейки в диапазоне» | `fraction_outside_range(PORO) == 0` | 0 — «все в диапазоне» ⇔ доля вне диапазона 0; сам диапазон `0.01…0.50` — из «Метод / формула» |
| `QC_PHYS_002` | «Все ячейки в диапазоне» | `fraction_outside_range(PERM) == 0` | то же; диапазон `0.001…10000` мД из метода |
| `QC_PHYS_003` | «Все ячейки в диапазоне» | `fraction_outside_range(SW) == 0` | то же; диапазон `0…1` из метода |

Проверка `tests/test_qaqc_checks.py` сверяет это правило машинно: каждое число
порога обязано встречаться в «Критерий» либо в «Метод / формула» того же пункта
чеклиста, либо попадать в перечисленные выше 7 случаев.

## 3. Атрибуция блоков: два расхождения с исходным чеклистом (зафиксированы, не скрыты)

1. **`QC_PHYS_*` в чеклисте лежат в блоке 11** («Контроль качества оценки
   неопределённостей»), а не в блоке 13. В пакет они отнесены к блоку **13**
   («Петрофизическое моделирование»), потому что это диапазоны φ, k, S_w, параметров
   Арчи и Козени-Кармана, и потому что `config.yaml → checks.package_blocks`
   привязывает `G-PETRO` к блокам 07/08/13 (у блока 11 гейта нет вовсе —
   `foundation`, `ontology/qa_gate_map.yaml`). Файл — `b13.csv`, в колонке `Блок` —
   имя блока 13. Решение согласовано с Lead-планом (`PLAN_AGENTS_v2.md`, таблица блоков).
2. **`QC_GS_001…006` и остальные группы** взяты с их «родными» блоками без изменений.

Генератор:
* не изменяет первые 652 строки `checks_table.csv` (сверяет SHA-256 с `baseline.json`);
* не меняет существующие записи `checks.py`/`check_functions.py` (переносит их дословно);
* падает (не «угадывает»), если: примитив не из схемы и не `unknown`; порог не парсится;
  число клауз порога ≠ числу ключей (для одноключевых метрик); ключ не описан в
  `model_keys.csv`; `%` в пороге у `mape`; ID дублируется.
